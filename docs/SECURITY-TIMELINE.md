### 2026-08-25: Official MCP PHP SDK unbounded SSE buffer denial-of-service disclosed and patched

- ID: `evt-2026-08-mcp-php-sdk-sse-buffer-dos`
- Status: **CONFIRMED** · Confidence: **CONFIRMED**
- Type: `vulnerability`
- Ecosystems: mcp, php, composer
- Dates: occurred `not recorded`, disclosed `2026-08-25`, updated `not recorded`
- Detector coverage: `not_detected`: The vulnerable code runs inside the mcp/sdk PHP client library at runtime against a remote MCP server response stream. AgentSec scans a local repository's static files and configuration and does not execute or fuzz a project's PHP dependencies, so no repository-shaped detector applies; a version-floor check against mcp/sdk < 0.7.1 in a composer.lock is the closest future detector shape but does not exist today.

A GitHub security advisory and CVE-2026-53965 described an unbounded in-memory buffer in the HttpTransport component of the official Model Context Protocol PHP SDK (Composer package mcp/sdk). Versions 0.5.0 through 0.7.0 appended every incoming Server-Sent Events chunk to a buffer with no upper bound and only flushed it on the SSE event delimiter, so a malicious, compromised, or man-in-the-middle MCP server that withheld the delimiter could exhaust the client process's memory and deny service. Fixed in mcp/sdk 0.7.1.

Sources:
- [modelcontextprotocol/php-sdk (GitHub Security Advisory): DoS: client HttpTransport SSE buffer (sseBuffer .= chunk) grows unbounded when server withholds the event delimiter](https://github.com/modelcontextprotocol/php-sdk/security/advisories/GHSA-7m52-jw36-44r3) (`github-ghsa-mcp-php-sdk-sse-2026`)
- [NIST NVD: CVE-2026-53965 Detail](https://nvd.nist.gov/vuln/detail/CVE-2026-53965) (`nvd-cve-2026-53965`)

Related: CVEs: `CVE-2026-53965`; techniques: `mcp.unbounded-buffer-dos`

### 2026-08-13: SiYuan MCP asset.upload path traversal disclosed and patched

- ID: `evt-2026-08-siyuan-mcp-asset-upload-path-traversal`
- Status: **CONFIRMED** · Confidence: **CONFIRMED**
- Type: `vulnerability`
- Ecosystems: mcp, siyuan
- Dates: occurred `not recorded`, disclosed `2026-08-13`, updated `not recorded`
- Detector coverage: `not_detected`: The flaw lives inside the SiYuan desktop application's own MCP tool implementation, not in a scanned repository's configuration or dependency manifest. AgentSec scans a local repository and does not analyze third-party desktop application binaries or their bundled MCP tool code, so no repository-shaped detector applies.

A repository security advisory and CVE-2026-82233 described a path traversal vulnerability in the asset.upload MCP tool shipped by the SiYuan note-taking application. Versions before 3.8.1 accepted arbitrary absolute file paths without a workspace boundary check, so a prompt-injected instruction to the built-in AI agent could copy files such as SSH keys or credentials from outside the workspace into the asset directory. Fixed in SiYuan 3.8.1.

Sources:
- [siyuan-note (GitHub Security Advisory): SiYuan MCP asset.upload Reads Arbitrary Absolute File Paths (Workspace Boundary Bypass)](https://github.com/siyuan-note/siyuan/security/advisories/GHSA-p23f-cm6q-2qp8) (`ghsa-siyuan-asset-upload-2026`)
