# AgentSec Triage v0.1 Alpha Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Security supersession:** Final alpha review disabled local Git-history scanning
> for untrusted repositories. The Task 9 Git subprocess steps below are retained as
> implementation history, not active detector coverage. Runtime scans now fail
> closed when `.git` exists until strict metadata confinement is available.

**Goal:** Ship a testable `v0.1.0-alpha` Python CLI that safely scans one local repository for Shai-Hulud/Keyv campaign indicators using a validated, bundled threat database.

**Architecture:** A zero-runtime-dependency Python package provides immutable result models, safe file discovery, a detector registry, deterministic human/JSON output, and strict completeness semantics. The authored YAML threat database is validated and converted at build time into bundled JSON; the first detector composes focused lockfile, installed-package, hash, and startup-config analyzers. The Git analyzer is a trusted-input internal utility and is unreachable from runtime detectors.

**Tech Stack:** Python 3.11+, stdlib runtime (`argparse`, `dataclasses`, `json`, `pathlib`, `hashlib`, `subprocess`), Hatchling, pytest, pytest-cov, Ruff, mypy, PyYAML and jsonschema as development/build dependencies, GitHub Actions.

## Global Constraints

- Runtime floor: Python 3.11.
- Runtime dependencies: zero; YAML and schema tooling are development/build dependencies only.
- The scanner is read-only, deterministic, and offline by default.
- The scanner never executes repository content and never follows symlinks outside the scan root.
- No incomplete or interrupted scan may return exit code `0` or claim a clean verdict.
- Exit codes are `0` complete/no findings, `1` findings, `2` incomplete/error.
- Every user-visible collection and serialized result uses deterministic ordering.
- Potential secrets and absolute user path prefixes are redacted when `--redact` is set.
- V0.1 implements only `shai-hulud-keyv`; ClawHavoc/ToxicSkills and persistence/trust-abuse are separate follow-up plans.
- Implementation uses test-driven development: failing test, observed failure, minimal implementation, passing test, focused commit.

```python
@dataclass(frozen=True, slots=True)
class Diagnostic:
    kind: DiagnosticKind
    path: Path
    message: str


@dataclass(frozen=True, slots=True)
class Finding:
    detector_id: str
    rule_id: str
    severity: Severity
    confidence: Confidence
    path: Path
    evidence: str
    campaign_ids: tuple[str, ...] = ()
    technique_ids: tuple[str, ...] = ()
    line: int | None = None
    remediation_url: str | None = None


@dataclass(frozen=True, slots=True)
class Coverage:
    files_seen: int = 0
    files_inspected: int = 0
    bytes_inspected: int = 0
    not_scanned: tuple[str, ...] = ()


@dataclass(frozen=True, slots=True)
class DetectorResult:
    detector_id: str
    applicability: Applicability
    findings: tuple[Finding, ...]
    diagnostics: tuple[Diagnostic, ...]
    coverage: Coverage


@dataclass(frozen=True, slots=True)
class ThreatDatabase:
    version: str
    updated: str
    package_versions: Mapping[str, frozenset[str]]
    wildcard_package_versions: Mapping[str, frozenset[str]]
    hashes: Mapping[str, str]
    domains: frozenset[str]
    commit_indicators: tuple[Mapping[str, str], ...]
    complete: bool = True


@dataclass(frozen=True, slots=True)
class ScanResult:
    tool_version: str
    database_version: str
    root: Path
    detector_results: tuple[DetectorResult, ...]
    diagnostics: tuple[Diagnostic, ...]
    elapsed_ms: int
```

Import `Mapping` from `collections.abc`. `ScanResult.complete` is a property that
is false when any aggregate or applicable-detector diagnostic has kind `ERROR`.
Its flattened `findings`, aggregate `coverage`, and deduplicated `not_scanned`
values are computed properties. `exit_code()` returns `2` when incomplete, then
`1` when any finding exists, otherwise `0`. `to_dict()` sorts detector results
by detector ID, findings by `(severity, detector_id, rule_id, path, evidence)`,
and diagnostics by `(kind, path, message)`.
